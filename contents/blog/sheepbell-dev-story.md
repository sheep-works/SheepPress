# 声でLQAする仕組み（SheepBell）をつくってみた

<div class="blog-post-meta"><span class="blog-post-date">📅 2026-10-17</span><span class="blog-post-tag">🛠 SheepTools</span></div>

ゲームやIT製品の翻訳では、LQAという作業があります。\
LQAとはLanguage Quality Asuranceのことで、「言語的品質保証」のこと。\
これは「翻訳したテキストがきちんと入っているか」を確認する作業です。\
よくあるトラブルとしては、

* 日本語が長くてはみ出してしまった

* おかしなところで改行されていた

* 違う訳文を入れてしまっていた

* 想定していた場所と違った（ポップアップのタイトルに「確認します。」のような文が出てしまったなど）

* コードや元の言語が残っていた

* 訳し方に一貫性が欠けていた

* フォントがきちんと整備されていなかった

* 翻訳のとおり操作しても、意図した動きにならなかった

などがあります。

こういったエラーを、実際にゲームやプロダクトを動かしながら見つけていき、レポートにまとめるのが **LQA** と呼ばれる作業になります。\
\
依頼を受けることは多いのですが、クライアントやテスターによってやり方も千差万別。\
報告フォーマットもExcelやGoogle スプレッドシートだったり、Jiraでイシューチケットを発行したりと様々。\
「こうやればいい」というベストプラクティスはまだ確立・共有されていないように思います。\
\
そこで、私が試行錯誤した過程と、その結果たどり着いた「SheepBell」開発による効率化まで、話をしてみたいと思いました。

## 最初期：とにかくプレイ！

私が初めてやったのはゲームのLQAでした。\
クライアントからもらったapkをインストールし、テストサーバーに接続。\
テスター用のアカウントでプレイし、気になった点を報告するというものです。\
\
初めてだったこともあり、まだどんなことが起きるのか想定しきれておらず、がむしゃらにプレイしながら、おかしいと思うたびに「スクショ」をしていました。ただ……\
\
「指が届かない……！」\
\
タブレットでやっていると、音量+電源ボタンが遠い！\
セリフの字幕などでおかしいと思っても、間に合わないことが発生！\
会話ログからなんとか拾えたものの……すぐにこれはマズイと気が付きます。

## ちょっと改良：スクリーン収録

そう、問題点だけを画像化しようとしたから大変だったのです。\
最初からすべて録画しておけば、後から探せるじゃないか！\
\
というわけで、アンドロイドで画面を録画しながらやってみると……\
\
熱い！端末の発熱がすごい！あ、落ちた……\
長時間の録画はつらいし、スクショよりも問題の位置を探すのが大変です。\

## さらに改良：OBS

というわけで、買ってきました。\
百均製のタイプC HDMI変換器と格安キャプチャーボード。\
これで録画はOBSに任せてしまえば、発熱やアプリ落ちなどは解決できます。\
\
ザッツ・お金の力。これでかなり快適になりました。\
\
しかもOBSならスクリーンショットもPC側に残せるので、報告書の前に画像を移動させる必要もありません。\

## まだまだ欲張る：左手デバイス

ただ、PCの前にいたとしても、操作中はタブレット。\
サッと一発でスクリーンショットをとるには、キーボードの「Ctrl+Shift+S」などを精確に押さなければなりません。\
\
というわけで、さらにお金の力を発揮し、XP Penの格安左手デバイスを追加。\
スクリーンショットや録画の開始/停止をワンボタンにすることで、失敗を未然に防ぎます。\
\
完璧な作業環境だ……と思っていましたが……

## やっぱり起きる： この画像なんだっけ？

快適なのでついつい「作業に集中」し、大量のスクリーンショットを貯めてから一気にレポートにまとめるスタイルに。\
\
すると\
\
「あれ？このスクショ、なんで保存してたんだっけ」\
\
というのがたびたび発生します。\
画像を拡大して、文字を隅々まで追ってやっと「あ、こんなところに訳抜けが」と再発見することも少なくありませんでした。\
\
また、再現手順を確認するのにはやはり動画を見返すことが必要です。\
でもスクリーンショットから動画の場所を特定するのはなかなか大変。\
作業後の手間は相変わらずでした。

## さらに追い打ち：アクションゲーム

上で画像にした事例はITプロダクトの例です。手順通り、順番に進めていけばOKなものでした。\
また、他にもシミュレーションゲームやカードゲームなら、パッと左手デバイスのボタンを押すぐらいの隙はあります。\
\
でも次にやってきたのはスピーディーなアクションゲーム。操作もキーボードではなくコントローラーです。\
\
これでは左手デバイスすら押せません。\
次はフットスイッチが必要か、と思っていたところ……\
\
そうだ、ヘッドセットにマイクがついているじゃないか！\
\
そうです、配信者だってゲームをしながら実況しているんです。\
それならバグを発見するたびに、吹き込んでしまえばいいのです！

## 構想段階：どうやって音声を見つける？

ただ、アクションゲームということだけあって、BGMもSEもガンガンなっています。\
自分の声を探そうと思っても、それは結局「動画をすべて見返すことと同じ」。\
\
ここでAIとの壁打ちを始めました。\

> 🐑：自分の声をBGMやSEとは識別できるようにしたい\
> \
> 💻：BGMやSEの音量が大きいと難しいかもしれない。スマホ等を使って音声ファイル自体を分けるのはどう？\
> \
> 🐑：それも一つの手だけど、録音ボタンを押すタイミングがズレたり、忘れたりしそう。音声データを分けるのはいいかも。OBSでは音声トラックを使えない？\
> \
> 💻：使えるよ。マイクだけトラック2に入れる設定は……\
> \
> 🐑：それってどうやったら使えるの？\
> \
> 💻：FFMpegで分割できるよ！

\
という感じで教えてもらえました。これはすぐにでも使えそう！\
早速やってみたところ……バッチリでした！自分の音声だけがクリアに残っています。\
さらにAudacityを使えば、「波形のある場所＝問題を発見した時間」なので、後から遡るのも簡単になります。\
\
これは革命的な進展でした。\

## そして、自動化へ

ここまで来たら、もう色々と自動でやってみたくなってしまいますよね。\
ここでもまたAIと壁打ち。

> \
> 🐑：うまくいったよ。でもこれをさらに自動化したい\
> \
> 💻：いいね、何を使ってどう自動化する？\
> \
> 🐑：波形のある場所を自動で収集してJSON化、それをもとに問題点のクリップをつくるのはどう？\
> \
> 💻：それならできそうだよ。Silero-VADで判定すればOK\
> \
> 🐑：あとせっかくだから、声も文字にできる？あ、APIとかは利用しない前提で\
> \
> 💻：Faster Whisperを使っちゃおう！\
> \
> 🐑：あ、そうだ。サブマシンで動かせれば、メインPCは作業を続けられるね。Google Colabで動かせる？\
> \
> 💻：簡単だよ。Gradioもいれちゃおう！

と、なりました。\
\
こうしてできたのがSheepBellです。\
アクションゲームをしながら、パッと「今改行がおかしかった」とだけ言うだけでOK。\
あとから音声分割 ＞ 文字起こし ＞ クリップ作成 までやってくれます。\
\
さらに、Excelにエクスポートもしたのですが、動画をみながら報告書の仕上げをしたいと思ったので、Web UIまでつくってみて……\
気づけば、私が欲しかった「LQA専用の付箋システム」ができあがっていました。\
もうこれなしにはLQAができない体質になっています。\
\
一連の流れを図にするとこうなります。

## 終わりに

他のSheep Toolsは翻訳の経験から必要な機能を練って、それから形にしていったものです。\
一方、このSheepBellは、あまりスタンダードのなかったLQAで「これが不便だ」「これは大変だ」と思ったポイントを、一つひとつ潰しながらつくったもの。\
まだ便利な知見が世に出回っていない作業だからこそ、ぜひ一度手に取ってみてください。\
