# 編集距離（レーベンシュタイン距離）を可視化する

<div class="blog-post-meta"><span class="blog-post-date">📅 2026-09-07</span><span class="blog-post-tag">🛠 アルゴリズム</span></div>

CATツールを使っていると、「この文とこの文は95％似ている」といった類似文のヒントが表示されます。\
これぞCATツールの真骨頂ではあるのですが、具体的にどんな処理をしているのか、気になりませんか？\
特に翻訳者にとって、一致率はだけど支払いに直結すのに、CATツールでブラックボックスになりがちな処理。知っていて損はないはずです！

というわけで、[編集距離を可視化して遊びながら学べるページ](https://comb.lambuage.com/play/edit-distance)をつくってみました！

## 編集距離とは

一致率の計算の元になるのが**「編集距離」**、つまり**「文字列Aを文字列Bに書き換えるのに、どれだけ手間がかかるか」**を数値化したものです。そしてそれを求める基本的なアルゴリズムが**「動的計画法を用いたレーベンシュタイン距離」**です。\
\
※実際には、製品ごとに細かな部分でカスタマイズされていると思います\
\
アルゴリズムの詳細を知るよりも、まずは触ってみるのが面白いでしょう。\
\
まずは「文字列A」と「文字列B」に好きなテキストを入力します（各20文字以内）。ある程度似た文を入れた方が、計算過程を実感しやすくなると思います。実験として以下の通り入力してみましょう。\
文字列A：ひつじのしつじ（羊の執事）\
文字列B：ひつじのじょーじ（羊のジョージ）

![](https://cms-assets.nilto.com/spaces/1659054838/media/1201566530/\_/edit-distance-input.png)

このように入力すると、まずは下のマトリックス部分が更新されます。

![](https://cms-assets.nilto.com/spaces/1659054838/media/1976190197/\_/edit-distance-matrix.png)

このマトリックスは横軸に文字列Aが、縦軸に文字列Bが1文字ずつ入力されたものです。

あとは**「計算を開始」**をクリックすると……

![](https://cms-assets.nilto.com/spaces/1659054838/media/166113631/\_/edit-distance-result.png)

![](https://cms-assets.nilto.com/spaces/1659054838/media/1348002540/\_/edit-distance-result2.png)

はい、計算が行われてCATツールの結果である62.5%が算出されました！

## ざっくり解説編

※本当にざっくりとしか解説しません。詳細を知りたい方は「じっくり解説編」まで飛ばしてください。\
\
この計算では、マトリックスの左上から1つずつ数字を埋めていきます。\
各マスに入る数字は**、「マトリックスの横軸と縦軸の文字」を1文字単位で見比べつつ、違った場合のみ最短経路に+1する」**、という単純なものです。

「ひ」を「ひ」に書き換えるのはコストゼロ。\
「し」を「じ」に書き換えるのはコスト1、といった具合ですね。\
こうして1文字ずつ見比べながら、編集にかかるコストを積み上げていき、最短経路を探します。そして右下に辿り着いたとき、文字列Aを文字列Bに書き換えるための「最短経路＝最短コスト」が分かる仕組みになっています。\
ただ、これはあくまで**「書き換えに必要なコスト」**。知りたいのは**「書き換えなくていい場所の割合」**です。なので、書き換えなくていい文字の百分率を求めてあげれば……\
はい、ご覧のとおり、**62.5%**の一致だと分かりました！パチパチ！

## じっくり解説編

ここからはアルゴリズムの考え方に沿って、ちょっと難易度高めでお送りします。\
まずは説明のためにいくつか用語を決めておく必要がありますね。\
※この時点で数学アレルギーが出てきたらバック推奨です。面白いと思った方はぜひ一緒に開発を！

### 呼称の定義

* **An**：文字列Aのn番目の文字（A0は空文字列）。たとえばA1は「ア」、A6は「ド」

* **Bn**：文字列Bのn番目の文字（B0は空文字列）。たとえばB1は「ア」、B6は「ム」

* **An-m**：文字列Aのn番目の文字からm番目の文字までをついないだ文字列。たとえばA1-5は「ひつじのし」

* **Bn-m**：文字列Bのn番目の文字からm番目の文字までをついないだ文字列。たとえばB1-5は「ひつじのじ」

* **LA/LB**：文字列A/Bの文字数。上記の例ではLAが7でLBが8

* **ベース列/行**：マトリックスの2列目/2行目のこと。下記の座標表記で(0, y)1または(x, 0 )となる点のこと

* **原点**：マトリックスの2列目2行目の交点

* **（x, y）**：マトリックス内の特定の交点の座標。原点を（0, 0）とする

* **編集操作**：削除、挿入、置換のいずれかの変更を加えること

* **コスト**：編集操作に必要な負荷のこと。通常は1

### 計算の流れ

#### マス目（交点）の意味

このマトリックスは文字列Aを文字列Bに書き換えることを目的としています。そのため、**交点(x, y)**に入る数字は、**A0-x**を**B0-y**に書き換えるために必要な編集操作の回数となります。

#### 目標

目標はマトリックスの右下に入るべき数字を求めることです（一番右が文字列A全体、一番下が文字列B全体を指すため、マトリックスの右下はそのまま文字列の書き換えに必要な数字になる）。

#### 求めるべき場所と計算手順

目標となるのが**右下(7, 8)**だと分かりました。では、そのためにはどこの数字が必要となるでしょうか？\
これは右下に隣接する**2点(7, 7) (6, 8)** と**左斜め上(6, 7)**の数字が分かれば自然と求められます。その理由は、各交点の意味するところを考えてみると分かりやすいです。

*  **(7, 7)**：「ひつじのしつじ」を「ひつじのじょー」に書き換えるために必要な編集操作

*  **(6, 8)**：「ひつじのしつ」を「ひつじのじょーじ」に書き換えるために必要な編集操作

*  **(6, 7)**：「ひつじのしつ」を「ひつじのじょー」に書き換えるために必要な編集操作

いずれも右下まで「あと1文字」となっています。なので、このいずれかの**「編集の最短経路」+「最後の1文字の編集操作」**が右下の数字になるはずです。\
ここで**A7（じ）**と**B8（じ）**を比べてみると、一致していることが分かります。つまり「**最後の1文字は書き換え不要**」ですので、**(7, 7) (6, 8) (6, 7)**のうち、いずれか最小の値が**(7, 8)**に入ることになります。\
\
では、この3つを求めるにはどうしたらいいでしょうか？3つ同時に考えるのは大変なので、1つ左のマス**(6, 8)** について考えてみましょう。\
**(6, 8)** の数字を求めるのも、先ほどと同様に**上(6, 7)、左(5, 8)、左上(5, 7)**が分かっている必要があります。もう一度各交点を詳しくみると、

*  **(6, 7)**：「ひつじのしつ」を「ひつじのじょー」に書き換えるために必要な編集操作

*  **(5, 8)**：「ひつじのし」を「ひつじのじょーじ」に書き換えるために必要な編集操作

*  **(5, 7)**：「ひつじのし」を「ひつじのじょー」に書き換えるために必要な編集操作

となっていますね。また、**A6（つ）**と**B8（じ）**は違う文字です。つまりここでは編集操作が必要となりますので、この**3つの最小値にコスト（1）を加算**すればOKです。\
\
このように**「右下を求めるために1マスずつ左の情報が必要」**ということを念頭に、どんどん遡っていくと最終的にベース列に辿り着きます。ここで今度は同様に、1つ上の行についても確認していくと……原点まで辿り着くことが分かるはずです。\
ベース列とベース行はすでに数字が分かっていますので、**(1, 1)** に入るべき数字はもう分かります。原点は空文字を空文字に編集する操作なので0、A1とB1は「ひ」で一致しています。なので、**(1, 1)** に入るべき数字は**0、1、1**の**最小値0**だと決まります。\
\
これを先ほど遡ったのとは反対に、右下まで1マスずつ埋めていくと……**編集距離「3」**が求められました！

#### 計算ルールの整理

ここでいったん、計算ルールの整理をしておきましょう。\
**交点(x, y)**の数字を求めるには、その**左(x-1, y)、上(x, y-1)、左上(x-1, y-1)**の数字が必要でした。この3つの最小値に対して、**Ax = By ならばそのまま使う、Ax ≠ By ならばコスト（1）を加算する**、という操作を繰り返していく、というふうに一般化できます。\
さらに進むと、左上から1マス右または下に進むと、挿入・削除の編集操作が必要なので、基本的には左上≧左（上）の関係が成り立ちます。\
そのため、**Ax = By ならば (x, y)=(x-1, y-1)、Ax ≠ By ならば (x, y) = (x-1, y-1) +1** となる、とも言えるでしょう。

#### 編集距離と一致率

ただ、編集距離が3だと分かっても、これと一致率はイコールになりません。なにせ、**「4文字のテキストのうち3文字が変更された」**ケースと、**「100文字のテキストのうち3文字が変更された」**では、重みが全く違います。なので、文字列A、Bの長い方の文字数で割って正規化してあげます。今回のケースでは、より長いのは文字列Bの8文字ですので、**3/8=0.375**となります。これは**「編集量」**であり、**「不一致率」**とも見なせるため、一致率にするため1から引いて100をかければ、**（1-0.375）\*100＝62.5%**の一致率だと求めることができました。

## 終わりに

この動的計画法（Dynamic Planning、DP）と呼ばれるアルゴリズムは、なかなかすぐには頭に入ってこないものです。じっくり解説編を読まれた方は、ぜひ一度、ステップ実行で一文字ずつ見比べながら確認してみてください！
